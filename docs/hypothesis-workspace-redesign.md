# 仮説構造化ワークスペースの再設計

## 調査・再利用

`main.html` の Golden Layout はキーワードマップと旧仮説マップを縦に配置し、別領域に仮説入力・SCAMPER支援を置いていた。直前の `hypothesis-network.js` はネットワーク／旧マップの切替、AI抽出、範囲ハイライト、候補編集・分割・採否、リンク推定を実装済みだった。

これらの処理と vis-network を継続利用。問いかけは既存の `buildScamperPrompt` と `fetchLatestScreenState` を再利用する。既存SCAMPER入力UIは右側の折りたたみ領域に移動した。キーワード整理、旧GoJSマップ、探究プロセスマップは保持する。

## 画面・操作

- 上段30%にキーワード生成（幅15%）とキーワードマップ（幅85%）、下段70%に探究プロセスマップを横幅全体で配置する。キーワード生成を再表示するときも上段の15%へ戻す。入力欄は最大64px、生成結果は欄内スクロールとし、キーワード欄を画面全高まで引き延ばさない。
- 仮説ワークスペースは下部の「仮説構造化ワークスペースを開く」から画面内に展開。左にマップ、右にサイドパネルを配置し、パネル幅を切替可能。
- ノード選択→詳細→「仮説を深める」→思考記述→AI抽出または範囲選択→候補編集・採用・除外→マップ追加を同一画面で実施。
- ノードのダブルクリックでも精緻化を開始する。過去のセッションは詳細またはセッション選択欄から再開できる。
- 精緻化の4方向は問いかけだけに使用し、種類やリンクは自動確定しない。
- 採用時に複数接続先、矢印方向、関係、自由ラベルを指定。接続なし・未分類も許容。
- リンクの追加・編集・削除、ノード編集・削除、ドラッグ、ズーム、パン、全体表示を保持。自動配置は階層を作らないグリッド配置。
- 旧マップの親子関係は未確定リンク候補として取り込み、意味や方向を強制しない。

構造化／精緻化および探究プロセスマップのタブ切替は廃止。探究プロセスマップと仮説構造化マップの表示位置を入れ替え、既存の編集UI・保存先・データモデルを維持する。仮説ワークスペースを閉じると元の配置へ戻る。キーワード生成は初期表示し、ヘッダーボタンで表示を切り替える。仮説追加ボタンはキーワード生成の表示状態に関係なく使用できる。

## データ・互換性

既存 `hypothesis.network` JSONをschemaVersion 2へ拡張。DBのテーブル変更や別保存APIは不要。

- nodes: 検討状態 `reviewStatus`、位置 `position` を追加。本文、種類、ID、日時、出典とSRO属性を保持。
- edges: 未分類、代替説明、補完と任意ラベルに対応。UIでは循環も許容し、種類による接続制限は設けない。
- sessions: 対象nodeId、思考記述text、問いquestions、判断履歴history、開始時の仮説本文hypothesisSnapshot、日時を保持。
- candidates: 既存のsourceId／sourceSnapshot／start／end／status／nodeIdを継承。セッションのIDを抽出元IDとして関連付ける。

旧schemaVersion 1はnormalizeで読み込み、セッション配列と検討状態の初期値を補完する。既存のworking/explanatory/operational分類と表示名を保持し、idea（working hypothesis）とunclassifiedを追加。旧JSONの追加フィールドも保持する。

精緻化記述は入力ごとにローカル下書きへ保存し、既存400msのDB自動保存へ接続。ノード選択の変更、本文の編集、セッションの追加で過去の記録を消さない。ノード削除時もセッションは記録として残す。確定済み候補を再採用してもノードを複製しない。

## 検証

- `npm run test:hypothesis-workspace`: 本番コントローラを最小DOMで実行。記述保持、手動候補編集、AI抽出の模擬応答、採用・除外履歴、複数接続、重複採用防止、選択変更、複数セッション、新ノードの精緻化、ノード編集後の履歴、JSON復元を確認。
- `npm run test:hypothesis-network`: 既存グラフ・ハイライト・互換マージの検証を継続し、本番サーバーのマージ関数でセッションが保持されることを追加確認。
- `npm run test:prompt-context`: 既存AIプロンプトの回帰確認。
- `npm run test:map-display`: 配置の入れ替え、拡大／復元、最大化中の領域サイズ、Esc、展開通知、編集内容の保持を確認。
- `node scripts/verify-process-map-support.js`: 探究プロセスマップの既存支援処理を確認。
- JS構文検査、`git diff --check`。
- Chromeで既存画面と仮データのマップ／サイドパネル表示を確認。
- 配置入れ替え後もChromeで既存データの中央プロセスマップ、仮説マップ初回展開、ノードの読みやすさ、右側パネル、Escによる復帰を確認。

## 制約・未検証

実AI応答と実MySQLへの保存・再読み込みを通した一連のE2E試験は未実施。AI・DBの応答は自動テストでは模擬し、保存・復元とサーバーマージを個別に確認した。一般の `npm test` は元から未設定。静的JSアプリで専用ビルド工程はない。

高度な適応的支援・仮説の質の自動判定は今回対象外。AI未採用候補はパネルとハイライトに表示し、確定マップのノードとしては表示しない。小画面でも左右のマップ・パネルを維持するため、十分な画面幅を推奨。既存SCAMPERの質問選択ダイアログは従来の動作を保持する。

## 表示の整備

`workspace-shell.css`をメイン画面限定で適用。ヘッダーを58pxの一列配置とし、テーマ切替をヘッダー内へ移動。タイトルの自動文字サイズは12〜16pxに制限。各編集領域の余白・ボタン・見出しを揃え、マップの最低高さによるはみ出しを解消した。キーワード生成欄は空の補助ラベルをレイアウトから除外し、入力と結果へ高さを配分する。

既存の外部配信jQuery 1.11.1、Golden Layout JS/CSSを同じ配信元から`JS/vendor`へ保存し、main.htmlではローカル配信する。新しいライブラリは追加していない。

## マップの拡大表示と読みやすさ

仮説ワークスペースの展開は縦に画面を伸ばさず、ヘッダー下から画面下端までの固定パネルとして表示する。右の編集パネルとキャンバスを残し、パネル内部だけをスクロールする。閉じる／Escで元へ戻り、編集中のマップを再作成しない。閉じた状態では仮説キャンバスの生成を保留し、展開時に読みやすい倍率で描画する。

キーワード・探究プロセスマップの「拡大表示」はGolden Layout既存の最大化／復元を使用。編集中のDOMやセッションを作り直さない。仮説・リンク一覧と分析は右側パネルへ移し、開いてもキャンバスを縮めない。

ネイティブの展開要素内で高さがつぶれないよう、仮説編集領域は固定パネルの内側へ直接配置する。初回の仮説キャンバス描画は表示領域の幅・高さが確保されてから行う。Golden Layoutのサイズ更新後に通常配置の再計算を重ねないようにし、拡大中のマップサイズを維持する。

各マップの「読める大きさ」は表示倍率の下限を適用する。大きなグラフでは一部が画面外に位置することがあるが、パン／ズーム／全体表示で参照できる。キーワードマップの領域リサイズではユーザーのズームとパンを維持する。

`node scripts/verify-map-display.js`で、配置の入れ替え・拡大対象の変更・復元・Esc・仮説ワークスペースの開閉通知・入力保持を確認する。
